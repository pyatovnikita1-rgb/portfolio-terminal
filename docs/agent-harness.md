# Подключение агентного harness

Проектные инструкции хранятся в корневом [AGENTS.md](../AGENTS.md), а описание
проекта, запуск и проверки — в [README.md](../README.md). Они не зависят от SDK,
модели или конкретного агентного приложения.

Harness здесь означает среду, которая передаёт агенту задачу и контекст,
предоставляет инструменты и управляет разрешениями. Для работы с этим проектом
ей достаточно уметь читать и редактировать файлы и выполнять команды.
Для визуальных правок нужен также доступ к браузеру.

## Как передать инструкции

1. Открой корень репозитория как рабочую директорию harness.
2. Если harness поддерживает чтение `AGENTS.md`, включи этот механизм и проверь,
   что загружен именно корневой файл этого проекта.
3. Если автоматического чтения нет, добавь стартовую инструкцию ниже в контекст
   сессии или в настройку проектных инструкций harness. Когда среда принимает
   только вложения, приложи актуальные `AGENTS.md` и `README.md`.
4. После смены harness или сброса контекста снова передай инструкции. Само
   наличие файла в репозитории не гарантирует, что среда его прочитает.

Стартовая инструкция:

```text
Работай из корня репозитория portfolio-terminal.
Перед изменениями прочитай AGENTS.md и README.md и следуй проектным инструкциям.
Проверь git status --short и сохрани существующие пользовательские изменения.
Затем выполни мою задачу. Проверки выбирай по README.md и фактическим изменениям.
В конце сообщи, что изменено, что проверено и что осталось непроверенным.
```

Если среда требует собственный файл правил, используй его как короткую точку
входа с указанием прочитать `AGENTS.md` и `README.md`. Конкретное имя файла и
синтаксис подключения выбираются по документации установленной версии harness.
Не копируй в него весь набор правил: общие инструкции должны обновляться в
одном месте. Если harness не умеет читать другие файлы, копию придётся обновлять
при каждом изменении оригинала.

## Проверка подключения

В новой сессии дай агенту короткую задачу без изменения файлов:

```text
Прочитай инструкции проекта. Назови файл страницы, где находятся её активные
стили, команду локального запуска и способ реализации ссылки на email.
Ничего не изменяй.
```

В ответе должны быть `index.html`, его встроенный `<style>`, команда
`python3 -m http.server 8000 --bind 127.0.0.1` и обычная ссылка `mailto:` для email.
Это проверка доступности контекста; если ответ неверный, проверь рабочую
директорию и способ загрузки файлов инструкций.

## Инструменты и разрешения

- Чтение и запись файлов нужны для изменений; shell и Git — для просмотра
  разницы и проверок. Node.js и установка npm-пакетов для текущего сайта не нужны.
- Python 3 нужен только для описанного в README локального HTTP-сервера.
  Можно использовать другой статический сервер, если он уже доступен.
- Браузер нужен для проверки вёрстки. Без него агент должен явно указать,
  что визуальная проверка не выполнена.
- Ключи моделей, разрешения shell, доступ к сети и параметры sandbox
  настраиваются в самом harness. `AGENTS.md` не выдаёт технических разрешений
  и не заменяет настройки среды. Секреты не хранятся в проектных инструкциях.

## Поддержка документации

Общие правила меняй в `AGENTS.md`, сведения о проекте и команды — в README,
порядок подключения — в этом файле. Если появятся отдельные правила для
подкаталогов, явно опиши порядок их загрузки: не каждый harness автоматически
обнаруживает вложенные инструкции.
