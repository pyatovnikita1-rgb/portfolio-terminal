# Инструкции для агентов

Эти правила действуют для всего репозитория. Это общий источник проектных
инструкций для любого агентного harness. Настройка подключения описана в
[docs/agent-harness.md](docs/agent-harness.md).

## Начало работы

1. Прочитай [README.md](README.md): назначение, структура, запуск и проверки.
2. Проверь `git status --short` и прочитай файлы, относящиеся к задаче.
3. Сохрани существующие пользовательские изменения. Не включай посторонние
   правки в свою задачу.
4. Выполняй конкретный запрос пользователя. Для обычных обратимых правок не
   добавляй отдельный этап согласования; уточняй только недостающие сведения,
   которые существенно влияют на результат.

## Устройство проекта

- Сайт — статический `index.html`, без пакетного менеджера, сборщика и backend.
- Текущие стили, токены и объявления шрифтов находятся в `<style>` внутри HTML.
- `system/colors_and_type.css` и `system/kit.css` содержат отдельную дизайн-систему,
  но сейчас не подключены к странице. Изменение этих файлов само по себе не
  меняет сайт.
- Шрифты загружаются локально из `system/fonts/`. Иконки и декоративные SVG
  лежат в `system/icons/` и `system/assets/`.
- Команды терминала на странице — элементы оформления. Исполнения команд,
  ввода пользователя и настоящей терминальной сессии нет.

## Правила изменений

- Сохраняй простую статическую архитектуру. Не добавляй framework, зависимости,
  сборку или сервисы без необходимости для запрошенной задачи.
- Следуй текущему оформлению кода; не переформатируй весь файл ради небольшой
  правки.
- Сохраняй терминальную композицию, тёмную палитру, фиолетовый акцент `#b026ff`
  и локальные шрифты, если задача не требует изменения дизайна.
- Тексты сайта и общения с пользователем — на русском; существующие команды
  терминала и названия ролей могут оставаться на английском. В блоке о себе
  использован строчный авторский стиль.
- Не придумывай биографию, стаж, достижения, контакты или текущий статус автора.
  Обновляй эти сведения по данным пользователя. Квартал в статусе не следует
  автоматически заменять на текущий.
- При изменении позиционирования проверь согласованность `<title>`,
  `meta[name="description"]`, блока `whoami` и текста о себе.
- При изменении интерфейса учитывай мобильную ширину, доступность с клавиатуры
  и семантику HTML. Сохраняй `lang="ru"`, понятные названия ссылок и `aria-hidden`
  у декоративных элементов; для новой анимации учитывай reduced motion.
- Не добавляй удалённые шрифты, трекеры, секреты или сторонние сервисы без
  необходимости для задачи. Контакты используют прямые ссылки, email — `mailto:`.

## Проверка и завершение

- Выбирай проверки по типу изменений из раздела «Проверки» в README.
  В проекте нет настроенных команд `npm test`, `npm run build` или линтера.
- Для правок документации проверь пути, ссылки, точность команд и
  `git diff --check`. Не добавляй тестовую инфраструктуру ради правки текста.
- Для HTML/CSS открой локальную страницу и проверь затронутое поведение на
  мобильной и настольной ширине. Если браузер недоступен, сообщи об этом;
  чтение исходника не заменяет визуальную проверку.
- Новые файлы проверь отдельно: обычный `git diff` не показывает содержимое
  untracked-файлов. Перед завершением снова проверь `git status --short`.
- Если меняешь структуру, команды запуска или рабочий процесс, обнови README
  и относящиеся к изменению инструкции в той же задаче.
- В финальном ответе кратко перечисли изменения, выполненные проверки и
  оставшиеся ограничения. Не утверждай, что проверка прошла, если не запускал её.
- Создавай коммиты, отправляй изменения и публикуй сайт, когда это входит в
  запрос пользователя. Иначе оставь изменения в рабочем дереве для просмотра.
